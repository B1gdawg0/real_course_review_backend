# Class Diagram Summary (Paragraph)

เอกสารนี้สรุปความหมายของ Class Diagram ใน [diagrams/class/class-diagram.md](diagrams/class/class-diagram.md) แบบย่อและเป็นย่อหน้าล้วน โดยอธิบายทั้งโครงสร้างข้อมูลหลัก (entities) และความสัมพันธ์ระหว่างกันในระบบ Real Course Review Backend.

ภาพรวมของไดอะแกรมแสดงโดเมนหลักของระบบรีวิวรายวิชา ได้แก่ ผู้ใช้ (User) รายวิชา (Course) อาจารย์ (Professor) รีวิว (Review) แท็ก (Tag) การโหวต (Vote) และการรายงาน (Report) โดยมีตารางเชื่อม (junction tables) เพื่อรองรับความสัมพันธ์แบบ many-to-many ระหว่าง Course–Professor, Course–Tag และ Review–Tag โครงสร้างนี้ทำให้ระบบสามารถเก็บข้อมูลรีวิว/คะแนน/การโหวต/การรายงาน และทำการจัดอันดับหรือค้นหาได้อย่างเป็นระบบ.

คลาส User แทนผู้ใช้งานในระบบและเก็บข้อมูลระบุตัวตน เช่น ชื่อ อีเมล และบทบาท (Role) เพื่อแยกสิทธิ์การเข้าถึง (เช่น USER, ADMIN) ผู้ใช้หนึ่งคนสามารถสร้างรีวิวหลายรายการได้ รวมถึงโหวตรีวิวและสร้างรายงานได้หลายครั้ง ซึ่งสะท้อนกิจกรรมหลักที่ผู้ใช้ทำกับเนื้อหาในระบบ.

คลาส Course แทนรายวิชาและเก็บข้อมูลรายละเอียดเชิงวิชาการ เช่น รหัสวิชา หน่วยกิต ภาคการศึกษา และประเภทวิชา รวมถึงข้อมูลที่ระบบคำนวณเพื่อการแสดงผลและจัดอันดับ เช่น ค่าเฉลี่ยคะแนน (Rate) จำนวนรีวิว (ReviewCount) และคะแนนจัดอันดับ (Score) นอกจากนี้ยังมีข้อมูลสำหรับการค้นหา (FTS) และสถานะการแนะนำ (RecStatus) ทำให้รายวิชาสามารถถูกเรียกดู จัดเรียง และค้นหาได้อย่างมีประสิทธิภาพ.

คลาส Professor แทนอาจารย์ผู้สอน โดยเก็บข้อมูลชื่อ อีเมล ตำแหน่ง รูปภาพ และรายละเอียดการติดต่อ/สถานที่ เพื่อรองรับการแสดงข้อมูลอาจารย์ในหน้าใช้งานจริง ความสัมพันธ์กับรายวิชาเป็นแบบ many-to-many ผ่านตารางเชื่อม ทำให้อาจารย์หนึ่งคนสอนได้หลายวิชา และวิชาหนึ่งวิชามีอาจารย์ได้หลายคน.

คลาส Review เป็นแกนกลางของระบบรีวิว เพราะเชื่อมโยงผู้ใช้กับรายวิชาและอาจารย์ โดยรีวิวหนึ่งรายการมีผู้เขียน (UserID) ผูกกับรายวิชา (CourseID) และอาจารย์ (ProfessorID) พร้อมรายละเอียดข้อความรีวิวและข้อมูลประกอบ เช่น คะแนนเฉลี่ย (AvgRate) คะแนนจัดอันดับ (Score/DecayedScore) จำนวนโหวตขึ้น/ลง (UpCount/DownCount) และสถานะการโหวตของผู้ใช้ปัจจุบัน (UserVote) รีวิวรองรับการไม่ระบุตัวตน (IsAnonymous) ข้อมูลเกรด/ปี/หมู่เรียน และมีสถานะเนื้อหา (เช่น publish/ban/delete/hidden) รวมถึงสถานะการแนะนำ (RecStatus) เพื่อช่วยควบคุมคุณภาพเนื้อหาและประสบการณ์ผู้ใช้.

คลาส Tag เป็นข้อมูลหมวดหมู่ที่ใช้ติดป้ายกับรายวิชาหรือรีวิว เพื่อช่วยให้ผู้ใช้เข้าใจลักษณะของวิชา/รีวิวได้เร็วขึ้นและช่วยการจัดกลุ่มข้อมูลใน UI ความสัมพันธ์ของ Tag กับ Course และ Review เป็นแบบ many-to-many ผ่านตารางเชื่อมที่เกี่ยวข้อง ทำให้ 1 วิชาหรือ 1 รีวิวมีหลายแท็กได้ และ 1 แท็กถูกใช้กับหลายรายการได้.

คลาส Vote แทนการโหวตต่อรีวิว โดยเชื่อมความสัมพันธ์ระหว่างผู้ใช้กับรีวิว และเก็บค่าการโหวต (เช่น upvote = 1, downvote = -1) โครงสร้างนี้ช่วยให้ระบบคำนวณผลรวมโหวตของแต่ละรีวิวและนำไปใช้ในการคำนวณคะแนนจัดอันดับ รวมถึงบังคับตรรกะว่าโดยหลักแล้วผู้ใช้หนึ่งคนควรมีการโหวตต่อรีวิวหนึ่งรายการได้เพียงสถานะเดียวในช่วงเวลาเดียวกัน.

คลาส Report แทนการรายงานรีวิวที่ไม่เหมาะสม โดยเชื่อมผู้ใช้ผู้รายงานเข้ากับรีวิวที่ถูกรายงาน และเก็บประเภทการรายงาน (ReportType) เหตุผล (Reason) และข้อมูลสถานะการจัดการ (เช่น RecStatus และ SolveReason) ทำให้ระบบสามารถติดตามการกลั่นกรองเนื้อหา ฝั่งผู้ดูแลระบบสามารถดูรายการรายงานและจัดการได้ตามสถานะ.

ตารางเชื่อม CourseProfessor, CourseTag และ ReviewTag ทำหน้าที่เชื่อมความสัมพันธ์ many-to-many ให้เป็นรูปแบบที่จัดเก็บในฐานข้อมูลได้จริง โดย CourseProfessor รองรับการจับคู่ระหว่างรายวิชากับอาจารย์ CourseTag รองรับการติดแท็กให้รายวิชา และ ReviewTag รองรับการติดแท็กให้รีวิว การแยกเป็นตารางเชื่อมช่วยให้ความสัมพันธ์มีความยืดหยุ่นและขยายได้โดยไม่ต้องฝังรายการซ้ำซ้อนไว้ใน entity หลัก.

โดยรวมแล้ว ความสัมพันธ์สำคัญในภาพคือ User เขียน Review ได้หลายรายการและมีปฏิสัมพันธ์กับ Review ผ่าน Vote และ Report ส่วน Course เป็นศูนย์รวมของ Review และเชื่อมกับ Professor/Tag ผ่านตารางเชื่อม ขณะที่ Review เองเชื่อมกับ Professor และรับ Vote/Report ได้หลายรายการ โครงสร้างนี้รองรับทั้งการแสดงผลหน้ารายละเอียดวิชา การจัดอันดับรีวิวด้วยคะแนนจากโหวต และการดูแลเนื้อหาผ่านระบบรายงาน.
